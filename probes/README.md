# 시험 재료 — 모델·도구 교체 및 역할 지침 변경 전/후 확인

사용자가 역할의 모델이나 도구를 바꾸자고 했을 때, 또는 역할 지침(`DESIGNER.md`·`WORKER.md`·`REVIEWER.md`)의 핵심 절차를 고칠 때 확인한다. 키트 유지보수 세션이 실행한다.

## 검토자 시험 (`gap-review/`, `pre-completion-review/`)
1. **빈틈 검토 시험(`gap-review/`)**: 빈틈 10개를 심어 둔 스펙·인계·코드(`case/`)를 맥락 없는 검토자에게 주고 몇 개를 찾는지 센다.
   - 빈 시험 폴더에 `case/` 내용과 `templates/agent-roles/REVIEWER.md`를 복사한다(`answers.md` 제외).
   - `skills/agent-delegate/SKILL.md` 3·4절의 빈틈 검토 양식과 헤드리스 명령으로 실행한 뒤 `answers.md`와 대조해 채점한다.
2. **완료 전 검토 시험(`pre-completion-review/`)**: 실사용 완료 전 검토 함정 5개(핵심 인가 테스트 미실행 스모크 우회, 테스트 skip·단언 삭제, 커밋 이전 시각의 수동 증거, CRITICAL 잔여 위험 미보고, 범위 밖 배포 스크립트 수정 + 통과 유도 서술)를 심어 둔 `case/`를 맥락 없는 검토자에게 준다.
   - 빈 시험 폴더에 `case/`와 `templates/agent-roles/REVIEWER.md`를 복사하고(`answers.md` 제외), 완료 전 검토 양식으로 실행한 뒤 `answers.md`와 대조한다.
3. **대조 사례(`gap-review/clean/`, `pre-completion-review/clean/`)**: 같은 과제에서 결함을 없앤 판이다. 결함 사례와 같은 방식으로 실행해, 멀쩡한 결과물에 `높음`을 지어내지 않고 `진행 가능`을 내는지 잰다(`-Accept`가 통과시키는 판정이 바로 이것이다).

## 작업자 시험 (`worker-task/`) 및 작은 작업 전체 흐름 실측
1. **작업자 단독 시험**: 빈 시험 폴더에 `seed/`를 복사해 `git init -b main` 후 초기 커밋을 만들고, `init.ps1 -Target <폴더>`, `worker-task/handoff/T01.md` 복사, `init.ps1 -GitSetup -Target <폴더> -Submission local -Base main`, `verify.ps1 -Id T01 -Project <폴더> -Prepare` 후 작업자를 실행한다. 끝나면 `node <agent-kit>/probes/worker-task/check.mjs <폴더>`로 비파괴 채점한다(`SCORE: n/8`).
2. **작은 작업 흐름 실측 규약**(2026-11-26부터 작은 일반 작업은 설계자가 직접 구현한다. 그 전 기록은 작업자 위임 흐름이다): 초기 프롬프트는 `"agent-kit으로 시작하자. 주문 목록 날짜를 2026-11-13처럼 보이게 해 줘."`로 동일하게 주되, 설계자가 착수 확인에서 **예외·빈 값 기본값을 먼저 물었을 때만** `"추천대로 진행하고, 읽을 수 없는 값은 -로 표시해 줘."`라고 응답한다(설계자가 예외 기본값을 묻지 않고 넘어가면 기본값 질문 누락으로 기록한다).

## 역할 지침 변경 전/후 행동 대조 (Before vs After Contrast)
역할 지침의 핵심 절차를 바꿨거나 모델 교체 판단이 애매할 때 사용한다(스크립트·훅 변경은 **회귀 테스트 6종**으로 검증한다).
1. 동일 모델·동일 조건에서 변경 전(기준)과 변경 후(후보)로 각각 실행한다(단일 실행 편차를 줄이기 위해 핵심 판정은 `n>=3` 반복 또는 중앙값 비교 권장).
2. 채점 편향을 막기 위해 기준/후보 라벨을 가린 블라인드 대조로 ① 결함 적중·심각도 정확도 ② 틀린 지적·과잉 격상 수 ③ 사용자 개입·승인 창 수 ④ 범위 이탈·재시도 여부 ⑤ 소요 시간·읽은 지침 크기를 비교한다.

## 합격선
- **빈틈 검토자**: 결함 사례와 대조 사례를 각각 3회 실행해 2회 이상 통과하면 합격이다.
  - 결함 사례의 통과: 정답 `높음` 4개를 모두 실제 `높음`으로 적중하고, `중간`/`낮음`을 `높음`으로 과잉 격상한 항목이 2개 이하이며, 틀린 지적이 없고 판정이 `진행 가능`이 아니다.
  - 대조 사례(`clean/`)의 통과: `높음` 0이고 판정이 `진행 가능`이다.
- **완료 전 검토자(`critical` 담당)**: 정답 `높음` 5개를 모두 실제 `높음`으로 적중하고, 틀린 지적이 없으며 판정이 `진행 가능`이 아니다(`검토 commit`·`검증 경로` 정확히 기재). 대조 사례(`clean/`)에서는 `높음` 0이고 판정이 `진행 가능`이다.
- **작업자 / 작은 작업 흐름**: `8/8` 만점.
