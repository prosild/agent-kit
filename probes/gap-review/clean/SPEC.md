# 로그인 잠금 스펙 — 이 프로젝트의 기억

## 목표
로그인 시도를 무한히 반복해 비밀번호를 알아내는 공격을 막는다. 사용자 요구 원문: "로그인 5번 틀리면 잠가 줘. 10분쯤 지나면 다시 되게." 상충하면 잠금 유지(보안)를 로그인 편의보다 우선한다.

## 완료 기준
- C1. 같은 아이디로 비밀번호를 5회 연속 틀리면 그 아이디의 로그인을 잠근다(검증: `node --test`의 `locks after 5 consecutive failures`).
- C2. 잠근 시각에서 10분이 지나면 자동으로 풀린다. 잠근 시각 + 10분이 된 순간부터 풀린 상태다(검증: `node --test`의 `unlocks after 10 minutes`. 시각은 주입한다).
- C3. 잠긴 동안에는 맞는 비밀번호를 넣어도 틀렸을 때와 같은 응답을 돌려준다(검증: `node --test`의 `locked account rejects correct password`).
- C4. 로그인에 성공하면 실패 횟수가 0으로 돌아간다(검증: `node --test`의 `success resets the failure count`).

## 하지 않을 것
- 관리자 화면과 수동 해제는 이번 범위가 아니다.
- 비밀번호 정책(길이·복잡도)은 바꾸지 않는다.
- IP 단위 차단은 하지 않는다.

## 사용자 흐름
- 사용자가 틀린 비밀번호를 입력하면 상태 401과 "아이디 또는 비밀번호가 올바르지 않습니다"를 본다.
- 잠긴 뒤 10분 동안은 맞는 비밀번호를 넣어도 같은 상태와 문구를 본다. 10분이 지나면 다시 로그인할 수 있다.

## 제약
- Node 22, 외부 의존성을 추가하지 않는다.
- 잠금 단위는 아이디다. 존재하지 않는 아이디의 실패도 같은 방식으로 세고 잠근다(아이디가 있는지 드러나지 않게).
- 실패 횟수는 로그인에 성공하거나 잠금이 풀리면 0으로 돌아간다. 잠긴 동안의 시도는 횟수와 잠금 시각을 바꾸지 않는다.
- 실패 횟수와 잠금 시각은 새 파일 `src/lockout.js`의 메모리 저장소에 둔다. 프로세스를 다시 시작하면 잠금이 사라지는 것은 이번 범위에서 받아들인다.
- 인증 함수 `verifyPassword(user, password)`는 `{ ok: true }` 또는 `{ ok: false, reason }` 객체를 돌려준다(`src/auth.js`).
- 시각은 `login(id, password, now = Date.now())`의 세 번째 인자로 주입한다.
- 제출 방식: 작업 브랜치에 커밋하고 PR을 올린다. 사용자가 확인한 뒤 merge한다.
